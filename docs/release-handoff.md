# MeetSpace 候选版本交接

## 示例来源与用途

本应用由 Codex 为此次示例新建。演示叙事中的“已开发完成”指进入测试 Skill 阶段时，功能已经实现并形成可运行的交接版本，不声称它原本来自某个真实公司的历史项目。

初始版本：1.0.0-rc.1。目标是展示测试 Skill 如何接手一个功能已完成、测试不充分的项目，补齐验收场景，获得可追溯的证据并支持发布决策。

不为了演示删除正确代码、故意削弱权限或安排固定故障。如果以后另做故障注入实验，必须用单独分支并明确标识。没有发现缺陷也是允许的真实结果。

## 推荐的验收切入点

下面是风险线索，不是已经完成的场景台账或已发现的缺陷清单。测试 Skill 应自行从确认后的需求设计并独立审阅场景，再结合代码补充实现检查。

- 两个真实登录会话同时抢同一个时段，核对数据库与通知结果。
- 成员直接调用管理员 API、取消他人预约、跨团队使用猜到的对象编号。
- 相邻、重叠、包含、跨日、过去、三十天边界、时区偏移与容量边界。
- 重试同一请求标识、修改内容后重试、取消后重试、失败响应后的界面行为。
- 停用仍有预约的会议室、重新启用、降低容量、最后一位管理员降权。
- 成员保持登录时被降权，下一次请求应按新角色授权。
- 取消后立即预约同一时段，核对预约、列表日程和通知是否一致。
- 服务重启、页面刷新、多浏览器状态、手机宽度与键盘操作。

# DR-005: 黑盒场景设计通过与阶段档案

## 状态

已记录的黑盒设计阶段产出，设计门禁 black_box_ready，应用验收未开展。
本轮基于 [DR-004](004-login-window-endpoint.md) 的用户决定继续设计，关闭 [DR-003](003-black-box-design-review.md) 所记四项缺口；保留原历史档案和结论。

## 背景

- 用户回答“按建议”，确认登录限频窗口在精确六十秒时排除第零秒尝试。
- 全部 96 条需求及稳定 ID 保留，其余 95 条正文不变。
- 新确认基线使旧审阅失效，需要修补场景并重新独立反事实审阅。

## 决策

- 黑盒设计继续使用 tests/delivery-acceptance/，保留 96 个场景及 105 个 AI 操作方法。
- 补齐新增会议室事务失败、精确六十秒端点、密码完整持久化范围、后续会话令牌生成的设计缺口。
- 本基线首轮独立审阅判定 90 条充分、6 条不足；修订后第二轮判定全部 96 条充分。
- 编译流程执行确定性黑盒门禁，退出码 0，全部三个门禁通过，保存状态 black_box_ready。
- 流程结束后在 [stage-04-black-box-ready 档案](../../tests/snapshots/stage-04-black-box-ready/README.md) 保存原始 JSON、两轮历史与文件哈希，供公开阶段对比。
- 不把场景设计通过解释为应用测试通过，本轮不执行实际应用路径。

## 影响

- 需求、设计和独立审阅通过 scoped SHA-256 绑定，后续实质修改需要刷新独立审阅。
- 设计方法里的测试资源、故障设施与证据要求尚待实际验证，不能视为已有通过证据。
- 发布验收仍需资源、白盒、真实执行与证据门禁，应用实现与原有冒烟测试保持原样。

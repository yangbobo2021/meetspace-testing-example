# DR-006: 白盒验收场景设计与独立审阅

## 状态

已记录的白盒设计阶段产出，63 个白盒场景独立审阅充分，实际应用验收未开展。
本阶段继续使用 [DR-004](004-login-window-endpoint.md) 的确认基线和 [DR-005](005-black-box-design-ready.md) 的黑盒设计，不改变业务需求或原黑盒场景及方法。

## 背景

- 用户要求开始设计生成完整的白盒测试验收场景，并保留阶段产出用于 GitHub 对比。
- 已确认全部 96 条需求，现有 96 个黑盒场景、105 个方法及独立黑盒审阅。
- 已安装 Skill 的白盒步骤位于完整验收流程中，尚无独立仅白盒设计启动阶段。

## 决策

- 按用户仅设计范围采用 app-delivery-acceptance Skill 的 Analyst／Reviewer 分工、台账模型与反事实审阅原则，不启动完整编译验收流程或执行应用。
- 固定 stage-04-black-box-ready 的实现修订 5a0fd19 和源文件 SHA-256，预期以确认需求为依据。
- 新增 63 个白盒场景、63 个方法，覆盖 63 个重要实现目标，全部 96 条需求均有白盒关联；合计 159 个场景、168 个方法。
- 每项白盒场景记录 target_condition、代码定位、需求关联、操作方法和证据要求，活跃台账固定在 tests/delivery-acceptance/。
- Reviewer 在生成前独立枚举 64 组路径，再逐场景和实现目标挑战遗漏；第一轮 60 条场景充分、3 条方法不足，第二轮关闭三项缺口。
- 第三轮核验 175 项源码引用与定位校正，业务条件、预期和方法不变；最终全部 63 个白盒场景充分。
- 原黑盒独立审阅与门禁仍有效，白盒独立结论保存在 white_box_review.json，不冒充黑盒审阅或执行证据。
- 项目补充设计检查退出码 0、white_box_design_ready，检查源与需求绑定、场景和方法、分支映射、独立审阅及哈希；它不是完整验收门禁。
- 独立审阅通过后设置 white_box_complete，流程结束后保存 [stage-05-white-box-scenarios 档案](../../tests/snapshots/stage-05-white-box-scenarios/README.md)，不修改原公开阶段。

## 影响

- 重要实现路径具备需求、代码、场景、方法和独立判断的追踪链；不声称实际分支覆盖率或任意缺陷均不存在。
- 熵控制、完整持久化出口观察、精确时钟与透明故障适配器仍是执行计划，实际能力必须在后续资源阶段验证。
- 旧身份迟到 401、微秒重放等静态疑似风险保留为待执行探针，未认定实测产品缺陷。
- 应用代码、原有冒烟测试和确认需求保持不变；发布验收仍须真实执行与独立证据门禁。

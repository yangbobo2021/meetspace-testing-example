# DR-008：既有测试代码覆盖率审计

## 状态

审计阶段已记录8组补测建议，当时尚未进入正式场景台账或完成独立审阅。
建议转为正式设计的后续处理见 [DR-009](009-coverage-supplement-scenarios.md)，本审计阶段的原结论与档案保留。

## 背景

用户要求测量当前全部测试的代码覆盖率，并根据未覆盖分支找出缺失测试场景。
首轮完整验收的失败与未证明结论保持 [DR-007](007-first-release-acceptance.md) 不变。

## 决策

- 固定 `stage-06-acceptance-run` 的应用源码，以原有冒烟及归档业务测试入口进行隔离覆盖测量。
- 分别报告后端与前端可执行行、分支出口，不把覆盖率或测试进程退出成功等同于验收通过。
- 将未命中位置映射到遗漏模式、已有设计未执行的分支、状态组合、环境限制及防御逻辑可达性。
- 补测建议保存在测试资产内，不改写确认需求、正式场景及方法台账、首轮运行或审阅结果。
- 按已授权的阶段管理方式保存 [阶段07审计档案](../../tests/snapshots/stage-07-coverage-audit/README.md)，保留已有标签和档案。

## 影响

- 后端行覆盖380/384（98.96%），分支124/124（100%）；前端行180/181（99.44%），分支165/177（93.22%）。
- 加权可执行行覆盖560/565（99.12%），但异常类型、标准库继承入口、事务时序及身份变化状态组合仍有缺口。
- 提出8组补测路径与5处防御逻辑分析项，具体矩阵、预期与证据要求见阶段07档案。
- 本审计不修复应用或提升发布安全结论，补测设计需审阅并在后续执行中取得真实证据。

# DR-011：发布候选版本的已知缺陷修复

## 状态

用户已授权按缺陷修复、完整验收、独立发布审阅顺序执行，且每个过程单独提交。
本记录承接 [DR-010](010-supplemental-coverage-cycle.md) 的失败证据，不改变阶段09的执行事实。
修复阶段通过开发回归与独立代码复核后，以 `stage-10-fixes` 保存版本，再启动测试Skill完整验收。

## 背景

首轮完整验收发现空日期、微秒重放、迟到401和通知时间缺失四类缺陷。
补测进一步确认未支持HTTP方法错误格式及自身降权后数据重试身份恢复问题。
正式需求仍为已确认的96条，场景基线仍为167条，不以修改需求或降低预期消除失败。

## 决策

- 保留查询参数显式空值，使空日期进入原日期验证，而非作为省略参数处理。
- 使用保留精度的规范化绝对时间比较幂等内容，零微秒的合法旧请求仍保持原摘要兼容。
- 将通知中的中文日期及时间按数字字段生成，避免操作系统strftime对中文格式的差异。
- 为继承的HTTP错误入口提供API JSON错误说明及稳定代码，保留未支持方法的拒绝结果。
- 给前端异步请求记录身份代次，只允许当前身份的401清除工作空间，保留当前身份失效时的退出行为。
- 自身降权真实提交后更新已知角色，并在身份查询失败后保存待确认状态，使用户重试重新读取session再载入数据。
- 保留原需求、原冒烟及所有历史失败运行，在修复阶段新增真实HTTP回归，并运行现有前端身份和加载竞态矩阵。
- 验证测试harness与正式预期的一致性，不将原失败时界面形态写成修复后必须保持的结果。
- 完整验收流程期间不修改产品，后续若发现新的产品问题，退出该运行、单独提交修复并对新修订复测。

## 影响

- 无数据库结构迁移，既有合法预约的同标识重放应保持兼容。
- 修复版本、验收证据和独立发布判断分别保存到后续阶段提交，已有标签与档案保持。
- 开发回归通过仅支持修复效果，不等于全部167条场景或发布门禁通过。

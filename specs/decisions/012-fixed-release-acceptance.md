# DR-012：修复版本的完整验收与追加缺陷

## 状态

已执行并归档，承接 [DR-011](011-release-defect-fixes.md)，不批准发布。
`stage-11-failed-acceptance` 保存708c9c0的完整执行、正式独立审阅和全新覆盖率。

## 背景

用户要求每个过程单独提交，已授权修复、完整验收与独立发布审阅。
测试Skill对固定修订的96需求、167场景、176方法完成执行及逐项证据审阅。

## 决策

- 保留执行汇总157通过、9失败、1未证明，另存独立审阅160通过、6失败、1未证明，不回写原结果。
- 将四个原生角色/身份迟到响应反例归入同一UI状态缺陷族，保留6个实际违反预期场景，不误称后台越权。
- 新发现问题在当前流程终结后开发修复，修复和重新完整验收分别提交。
- 非法角色数组/对象的500与无副作用保留原证据，下一开发阶段增强类型校验，保留原严格断言。
- 自动审批拒绝旧app生成器的固定修订冲突后，本轮历史数据库兼容分支保持未证明，不绕过拒绝。
- 下一轮明确审阅合成历史表示夹具的来源与边界，仅运行新目标修订，不能冒充旧app新执行。
- 新修复后重新刷新重要实现路径设计、全部167场景执行及覆盖率，旧计数和旧passed不能迁入。

## 影响

- 708c9c0后端行及分支100%，前端行99.49%、分支97.39%；高覆盖率没有抵消迟到响应的状态组合失败。
- 需求仍96条，场景稳定ID仍167个；后续可在原方法中明确扩充竞态状态并独立复审。
- 已有标签和失败档案保留，下一开发修复继续执行用户已授权的发布准备范围。

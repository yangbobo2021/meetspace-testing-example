# application-runtime: 本地运行、示例数据与持久化

## 意图

使本地示例可独立启动、保存业务记录，并提供可识别的运行状态。
本包不定义公网运营、高可用、备份恢复或企业部署要求。

## 外部行为

### application-runtime-1

给定 Python 3.11+ 且具有 Asia/Shanghai 时区资料，当使用者执行 `python3 -m app.server`，应用应仅使用 Python 标准库在 `127.0.0.1:8766` 启动，并使用项目的 `data/meetspace.sqlite` 数据文件。

### application-runtime-2

当使用者通过启动参数指定 host、port 或 db，应用应使用指定监听地址、端口或数据库路径，未指定的参数保持默认值。

### application-runtime-4

当应用打开已有团队记录的数据文件，应用应保留其原有记录，不重复填入或按当前日期移动初始示例会议。

### application-runtime-5

当使用相同数据库文件重启服务，应用应保留已保存的团队、账号角色、会议室、预约、取消记录及通知的内容和已读状态。

### application-runtime-6

当客户端查询健康接口，应用应无需登录即可返回数据库可读取时的 ok 状态、1.0.0-rc.1 版本和 Asia/Shanghai 时区。

### application-runtime-7

当应用对接口请求返回错误，应用应使用 JSON 错误说明与稳定错误代码，不把内部异常栈或密码放入公开响应。

### application-runtime-8

当持久化或服务处理发生异常，应用应按以下错误类别返回结果：

| 类别 | HTTP 结果 |
| --- | --- |
| 数据完整性冲突 | 409 与 data_conflict |
| 数据存储操作失败 | 503 与 storage_unavailable |
| 未预期应用异常 | 500 与 internal_error |

### application-runtime-9

当一个业务写入事务失败，应用应撤销该事务的部分写入，不将未完成的修改保存为成功结果。

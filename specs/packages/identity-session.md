# identity-session: 身份、会话与请求保护

## 意图

使示例用户以所属团队与当前角色进入工作空间，并限制失效会话和非同源修改请求。
本包描述已有账号的登录，不包含注册、密码修改或企业身份接入。

## 外部行为

### identity-session-1

当用户提交登录资料，身份服务应按以下输入规则接收邮箱与密码：

| 字段 | 规则 |
| --- | --- |
| 邮箱 | 字符串，去除首尾空格后为一至一百六十字符，按小写匹配账号 |
| 密码 | 字符串，去除首尾空格后为一至二百五十六字符 |

### identity-session-2

当用户以有效账号的正确密码登录，身份服务应建立该账号的会话。

### identity-session-3

当登录账号不存在或密码不匹配，身份服务应以同一“邮箱或密码不正确”反馈拒绝登录。

### identity-session-4

当已登录用户查询当前身份，身份服务应返回用户编号、邮箱、姓名、所属团队编号与名称、当前角色、版本和 Asia/Shanghai 时区。

### identity-session-5

当没有有效会话的请求访问工作空间业务接口，身份服务应拒绝访问并要求登录。

### identity-session-6

当会话建立后经过八小时，身份服务应使该会话失效，普通业务访问不延长有效期。

### identity-session-7

当同一浏览器成功登录另一个账号，身份服务应替换该浏览器的原会话，不注销其他浏览器的有效会话。

### identity-session-8

当已登录用户退出，身份服务应撤销当前会话并清除该浏览器的会话 Cookie。

### identity-session-9

当同一来源 IP 提交登录请求，身份服务应在滚动六十秒内仅接收前八次资料格式有效的尝试，并对额外尝试返回频率限制，成功尝试同样计数。

### identity-session-10

当客户端提交 POST 或 PATCH 修改请求，请求入口应拒绝缺少 `X-Meeting-App: 1` 标记或携带不同于当前 HTTP 来源的 Origin 的请求。

### identity-session-11

当客户端提交 POST 或 PATCH 修改请求，请求入口应仅接收 `application/json` 的对象正文，正文长度须为一至六万五千五百三十六字节。

### identity-session-12

当身份服务建立或清除会话 Cookie，身份服务应将 Cookie 限制为路径 `/`、HttpOnly 和 SameSite=Lax。

## 内部行为

### identity-session-13

当账号密码被初始化，身份服务应仅保存带随机盐的密码派生值，不保存可恢复的明文密码。

### identity-session-14

当会话建立，身份服务应在持久存储中只记录随机会话令牌的摘要、用户关联与到期时间。

## 验证

本阶段仅整理需求，尚未新增验证条目、场景、执行结果或证据。
逐行为的集成与系统验证由后续测试阶段补充。
